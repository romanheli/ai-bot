# ai-bot — паспорт проекта

Telegram-бот Epsilon: пользователь пишет вопрос — бот отвечает через Gemini (Google AI Studio, REST).
Пускает только id из ALLOWED_IDS (+ ADMIN_ID), в группах молчит. Запуск пока на ПК: `.venv\Scripts\python bot.py`.

## Что умеет
- Главное меню (/start и кнопка «Главное меню»): текст приветствия, курсивом «создатель - имя» ссылкой на профиль
  создателя (у Telegram нет мелкого шрифта), кнопка «отправить интимку автору» ведёт в тот же профиль.
  Меню исчезает после первого вопроса.
- Представляется как Epsilon, отвечает официально, на «вы» (SYSTEM_PROMPT в ai.py).
- Помнит последние 5 пар (вопрос, ответ) на пользователя — в памяти, при перезапуске пропадают.
- После первого ответа внизу появляются кнопки «Очистить сессию» и «Главное меню» и остаются постоянно.
- «Очистить сессию» — предупреждение «После очистки сессия не сохранится» с кнопками Принять/Отменить;
  при пустой истории сразу «Сессия уже пуста.» (прошлое «Сессия очищена.»/«Сессия уже пуста.» при этом удаляется).
  «Принять» удаляет отслеженные сообщения чата младше 47 ч (Telegram не даёт удалять старше 48 ч), стирает историю,
  само предупреждение редактирует в «Сессия очищена.» (без кнопок), ниже меню. Нижние кнопки на ПК после этого
  пропадают до следующего ответа (их держало удалённое сообщение, а к отредактированному их не прицепить) —
  пользователь выбрал так. Не вышло отредактировать — предупреждение удаляется, «Сессия очищена.» приходит новым
  сообщением с нижними кнопками. Кнопка от прошлого запуска бота — сообщение просто удаляется, без ответа и лога;
  повторное нажатие под уже отредактированным — ничего.
- Если вопрос пришёл, пока бот ещё отвечает на прошлый (от того же пользователя) — «Подожди, ещё отвечаю
  на прошлый вопрос.», в очередь не ставится.
- Пока Gemini думает — «печатает…» (обновляется каждые 4 с).
- В консоли сервера при запуске — ярко-зелёная рамка «EPSILON ЗАПУЩЕН» с временем МСК (через logging: print падал бы на кириллице).
- Ответ всегда одним сообщением: промпт просит ≤4096 символов, Markdown вычищается (жирный, ссылки, инлайн-код,
  блоки кода), длиннее 4096 — обрезка по абзацу/предложению/слову с «…».
- Если Gemini отказалась отвечать на вопрос (blockReason) — «Нейросеть отказалась отвечать на этот вопрос —
  попробуй переформулировать.», другие модели не пробуются.
- Чужие (не из ALLOWED_IDS) — «Нет доступа»; ответ чужому и лог владельцу — не чаще раза в час на один id,
  иначе молча игнорирует. В группах молчит всегда.
- Нет сети при старте (обрыв, например на getMe) — не «Бот упал», а пауза и повтор (пауза растёт, максимум 5 мин).
- Лог владельцу через отдельного лог-бота: вопросы (+ модель, время, первые 300 символов ответа), ошибки Gemini,
  попытки без доступа, очистка сессии, запуск бота, остановка («Бот остановлен») и падение («Бот упал» + ошибка);
  если процесс убили без сигнала — при следующем запуске «Прошлый запуск оборвался» (метка .running), раз в неделю — «Недельный лимит Claude сбросился: дд.мм.гггг 03:00 МСК»
  (вс 00:00 UTC; если сервер в этот момент лежал — за эту неделю не придёт). Токены ботов вырезаются из логов
  и консоли. Сломанный лог ответу не мешает.
- Модели: gemini-3.5-flash-lite, запасная gemini-3.1-flash-lite
  (404/408/429 и любой 5xx, а также пустой ответ — следующая модель; таймаут 30 с на модель;
  остальные 4xx (400, 402, 403…) — сразу ошибка).

## Файлы
- bot.py — настройки из .env, обработчики (build_dispatcher), typing, main.
- ai.py — запрос к Gemini (ask), clean/fit под Telegram.
- тесты: test_ai.py, test_bot.py, testutil.py (фейки Telegram и Gemini). `.venv\Scripts\python -m unittest`

## Настройки (.env, образец — .env.example)
BOT_TOKEN, LOG_BOT_TOKEN, ADMIN_ID, ALLOWED_IDS, GEMINI_API_KEY, CREATOR_USERNAME, необязательно GEMINI_MODELS, CREATOR_NAME.
CREATOR_USERNAME — username создателя, ссылка https://t.me/<username>. CREATOR_NAME — имя в меню, по умолчанию @username.
Лог-боту владелец должен один раз написать /start, иначе Telegram не даст ему писать.

## Деплой
- Wispbyte, сервер, где раньше была Gamma (Gamma выключена с 2026-09-27, вернуть — только по команде пользователя).
  Код берётся из публичного https://github.com/romanheli/ai-bot (без логина/токена), App py file = bot.py,
  Auto Update = 1: после пуша пользователь жмёт Restart. Переменные — страница Environment (пишет .env на сервере).
- Startup Command: перед `/usr/local/bin/python` должен стоять `exec` — иначе хостинг не пробрасывает сигнал
  Stop боту (питон запускается дочерним процессом), и хостинг просто убивает процесс: в лог не придёт
  «Бот остановлен», а при следующем запуске придёт «Прошлый запуск оборвался». С `exec` сигнал доходит до бота.
- Пушить в оба репозитория: `git push romanheli main` и `git push origin main` (приватная копия wgtujtut-4/ai-bot;
  в адресе origin прописан `wgtujtut-4@`, иначе Git Credential Manager подставляет аккаунт romanheli).
- Сервер на Python 3.11: в f-строках не повторять внешние кавычки внутри {} и не ставить там обратный слеш.
